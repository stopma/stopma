# STOP.ma

منصة مغربية لنقد السلوكيات، مع مراجعة بشرية إلزامية قبل النشر. واجهة عربية، Next.js App Router + TypeScript + Supabase/PostgreSQL، جاهزة للنشر على Vercel. لا توجد بيانات تجريبية أو عدادات مصطنعة في التطبيق.

## التشغيل

Node.js 22.13+ وnpm:

```sh
npm ci
cp .env.example .env.local
# املأ المتغيرات محلياً فقط
npm run dev
npm run test
npm run typecheck
npm run build
```

على هذا الجهاز، إن لم يكن npm ضمن PATH، البديل المثبت محلياً هو `node .local/package/bin/npm-cli.js` (مجلد محلي مستثنى من Git).

بدون إعداد Supabase يظهر وضع التحضير، ولا يدّعي التطبيق نجاح الإرسال أو وجود زوار. لا يوجد تخزين وهمي بديل.

## قاعدة البيانات

1. أنشئ مشروع Supabase في حساب المالك، وحدد منطقة الاستضافة بعد تقييم متطلبات نقل البيانات.
2. نفذ `supabase/migrations/202609120001_initial.sql` مرة واحدة على مشروع جديد باستخدام SQL Editor أو Supabase CLI migrations.
3. ضع Project URL وanon key وservice role key في `.env.local` ثم في بيئة Vercel. لا تضع service role أو visitor secret ضمن NEXT_PUBLIC.
4. أنشئ مستخدم المدير في Supabase Authentication، وعطّل التسجيل العام. عيّن UUID في `ADMIN_USER_ID`. لا توجد أي إمكانية للتسجيل عبر الموقع.
5. أنشئ `VISITOR_SECRET` عشوائياً بطول 32 حرفاً أو أكثر، مثلاً `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` محلياً. تغييره يبطل معرّفات الزوار الحالية.
6. فعّل Supabase Cron وجدول `select public.cleanup_data();` يومياً. راقب نجاح المهمة. الجداول تستخدم RLS ولا تمنح anon/authenticated أي وصول؛ service role مستخدم على السيرفر فقط.

## الإدارة

`/admin`: دخول بكلمة مرور Supabase Auth، والتحقق من UUID على السيرفر في كل عملية. قوائم Pending / Published / Rejected، تعديل النص والفئة، الموافقة والرفض والإرجاع للمراجعة، تصفح 20 سجلاً في الصفحة، سجل مراجعة، فئات قابلة للتعديل، وإحصائيات فعلية.

كل إرسال يأخذ `pending` على السيرفر. دالة التصويت تتحقق من النشر وتأخذ قفل سجل، وتستعمل unique(stop_id, visitor_identifier) وتحديثاً ذرياً للعداد. لا توجد API عامة لتعديل الحالة.

## الخصوصية ودقة الإحصائيات

ملف ارتباط HttpOnly/SameSite بمعرف عشوائي موقّع، سنة واحدة. بصمة HMAC في قاعدة البيانات. لا اسم، لا رقم هاتف، لا CIN، لا IP خام في جداول التطبيق. تحديد المعدل يعتمد على بصمة IP من ترويسة Vercel الموثوقة فقط؛ على localhost يشترك الاختبار في الحصة المحلية. استضافة أخرى تحتاج تعديل مصدر عنوان الشبكة الموثوق.

إجمالي الزوار = معرّفات متصفحات فعلية منذ البداية؛ ليس عدداً مؤكداً للبشر. نفس المتصفح لا يتكرر، لكن حذف cookies أو استخدام أجهزة مختلفة يمكن احتسابه من جديد. المتصلون = آخر نبضة خلال دقيقتين، كل 30 ثانية والصفحة مرئية فقط. اليوم حسب Africa/Casablanca. دخول المدير يحذف زيارته المعروفة ويستبعد نبضاته؛ الزيارة قبل تسجيل الدخول من جهاز آخر لا يمكن نسبها إليه.

التصفية الآلية محدودة ومتحفظة: لا تضمن اكتشاف جميع الأسماء أو التشهير أو اللغة العدائية. المراجعة البشرية إلزامية لكل مشاركة. الحماية تشمل تحديد معدل موزع في PostgreSQL، مفتاح تصويت فريد، honeypot، فحص Origin، تحقق Zod، escaping من React وحدود المدخلات. هذه وسائل لتقليل الإساءة وليست ضمان منع بوتات موزعة؛ راقب الإساءة وفعّل Vercel WAF/challenge عند الحاجة.

## إطلاق مسؤول

`SITE_LAUNCH_READY=false` افتراضياً لمنع جمع بيانات عامة قبل الإعداد. يجب على المالك تحديد `PRIVACY_CONTACT_EMAIL` وهوية المسؤول عن المعالجة، ومراجعة سياسة الخصوصية، وتحديد المتطلبات الواجبة لدى CNDP وفق 09-08، بما فيها نقل البيانات للخارج. هذا التنفيذ لا يدعي الحصول على موافقة قانونية.

مراجع رسمية: [القانون وإجراءات CNDP](https://www.cndp.ma/) و[طلب نقل البيانات للخارج](https://www.cndp.ma/wp-content/uploads/2023/12/CNDP-Transfert-Etranger.pdf).

بعد تأكيد ذلك والإعداد الفعلي، ضع `SITE_LAUNCH_READY=true`. يفتح الإرسال والتصويت والإحصائيات والفهرسة. عطّل تسجيل مستخدمين جدد في Supabase، وراجع الاسترداد وحماية حساب المدير والنسخ الاحتياطي قبل الإطلاق.

## Vercel وSTOP.ma

ارفع المستودع إلى GitHub باسم `stop-ma` (خاص افتراضياً)، ثم Import في Vercel، Next.js preset. أضف المتغيرات المذكورة، وحدد `NEXT_PUBLIC_SITE_URL=https://stop.ma` بعد ربط النطاق؛ خلال التحقق استعمل عنوان Vercel الفعلي. هذه القيمة تتحكم أيضاً في Origin المسموح، لذلك يجب إعادة النشر عند تغييرها.

أضف `stop.ma` و`www.stop.ma` من إعدادات Domains. استعمل سجلات DNS التي يعرضها Vercel للمشروع نفسه، دون تخمين أو حذف MX/TXT الحالية. اجعل stop.ma الأساسي وأعد توجيه www إليه. تحقق من ملكية النطاق وHTTPS لكليهما. لا يوجد ربط نطاق تلقائي بدون صلاحية مالكه.

## الاختبارات

`npm test` يشغّل فحص المحتوى واختبار PostgreSQL حقيقي داخل PGlite (للاختبار فقط): Pending الافتراضي، مراجعة ونشر، تصويت فريد ومتزامن، عدادات، زيارات اليوم والحضور، انتهاء الحضور، حد الطلبات، منع anon/authenticated، سحب النشر وحذف البيانات المنتهية.

قبل الإنتاج اختبر مع مشروع Supabase فعلي وحساب المدير: إرسال → عدم الظهور علناً → الدخول → تعديل → موافقة → ظهور → تصويت → منع التكرار → رفض/سحب. تحقق من استقلال الأجهزة ومن دقة الإحصائيات واستبعاد المدير. اختبر واجهة الهاتف والكمبيوتر، الأخطاء، الحقول الفارغة، والرابط غير الموجود.

## تنظيم الملفات

- `src/app`: الصفحات وAPI وSEO.
- `src/components`: الواجهة العامة ولوحة الإدارة.
- `src/lib/server.ts`: الوصول للسيرفر والمصادقة والحماية.
- `src/lib/content.ts`: التحقق والتصنيف.
- `supabase/migrations`: الجداول ودوال المعاملات والسياسات.
- `tests`: الاختبارات.

اللغة الحالية ar-MA، مع نصوص واجهة معزولة في مكونات صغيرة. يمكن إدخال قواميس fr/en ومسارات locale لاحقاً دون تعديل مخطط البيانات. لا حسابات عامة. التعليقات متاحة داخل صفحة STOP فقط، بمراجعة يدوية قبل النشر؛ راجع [توثيق التعليقات](docs/comments.md) للجداول والحماية والاختبارات وصلاحياتها الخاصة.
